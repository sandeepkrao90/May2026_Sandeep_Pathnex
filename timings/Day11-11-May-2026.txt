# Advanced Kubernetes + EKS Interview Revision Notes

These notes are focused on:

* DevOps interviews
* Production support interviews
* Cloud/Platform Engineering interviews
* EKS-based environments

---

# 1. What is EKS?

## Amazon EKS (Elastic Kubernetes Service)

Managed Kubernetes service by AWS.

AWS manages:

* Control Plane
* API Server
* ETCD
* High Availability

You manage:

* Worker Nodes
* Applications
* Networking
* Security

---

Components:

* VPC

* EBS/EFS

# 4. Ingress

Used to expose HTTP/HTTPS applications.

Features:

* SSL termination
* Path-based routing
* Host-based routing

Example:

yaml

apiVersion: networking.k8s.io/v1
kind: Ingress


In AWS EKS:

* AWS Load Balancer Controller creates ALB.

---

# 5. Horizontal Pod Autoscaler (HPA)

Automatically scales pods based on:

* CPU
* Memory
* Custom metrics

Example:


kubectl autoscale deployment nginx --cpu-percent=70 --min=2 --max=10


Interview Point:

* Requires Metrics Server.

---

# 6. Vertical Pod Autoscaler (VPA)

Adjusts:

* CPU
* Memory requests/limits

Not pod count.

---

# 7. Cluster Autoscaler

Scales worker nodes automatically.

In EKS:

* Adds/removes EC2 nodes based on workload.

---

# 8. RBAC (Role-Based Access Control)

Controls permissions in cluster.

Components:

* Role
* ClusterRole
* RoleBinding
* ClusterRoleBinding

Example:


kind: Role
kind: RoleBinding


Interview Tip:

* Namespace-specific → Role
* Cluster-wide → ClusterRole

---

# 9. Service Accounts

Identity for pods.

Used with:

* IAM Roles for Service Accounts (IRSA)

Very important in EKS.

---

# 10. IRSA (IAM Roles for Service Accounts)

EKS feature allowing Pods to access AWS services securely.

Example:

* Pod accesses S3 without static credentials.

Benefits:

* Better security
* Least privilege access

---

# 11. Kubernetes Probes

## Liveness Probe

Checks if container is alive.

If failed:

* Pod restarted.

---

## Readiness Probe

Checks if pod ready to receive traffic.

If failed:

* Traffic not routed.

---

## Startup Probe

Used for slow-starting apps.

---

# 12. Resource Requests & Limits


resources:
  requests:
    memory: "128Mi"
  limits:
    memory: "512Mi"


Purpose:

* Prevent resource starvation
* Better scheduling

Interview Tip:

* Requests = guaranteed
* Limits = maximum allowed

---

# 16. Persistent Volumes

## PV (Persistent Volume)

Actual storage resource.

## PVC (Persistent Volume Claim)

Request for storage.

In AWS:

* EBS
* EFS

---

# 17. EBS vs EFS in EKS

| EBS                | EFS                 |
| ------------------ | ------------------- |
| Block storage      | Shared filesystem   |
| Single AZ          | Multi-AZ            |
| Single node attach | Multiple pod access |

# 30. CrashLoopBackOff

Meaning:

* Container repeatedly crashing.

Common reasons:

* Wrong command
* Missing env vars
* DB connection failure
* Application error

---

# 31. OOMKilled

Meaning:

* Pod exceeded memory limit.

Fix:

* Increase memory limit
* Optimize app
