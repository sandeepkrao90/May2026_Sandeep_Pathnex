What is Ansible?

Ansible is an open-source configuration management, automation, orchestration, and provisioning tool used in DevOps and Cloud environments.

It helps automate:

Server configuration
Software installation
Infrastructure provisioning
Application deployment
Patch management
Security hardening
CI/CD workflows

Ansible is very popular because:

Agentless (no software needed on target servers)
Uses simple YAML syntax
Easy to learn
Works well with Linux, Cloud, Kubernetes, Docker, Networking devices
Why Ansible is Needed in DevOps

Without Ansible:

Manual server setup

Time-consuming deployments

With Ansible:

Ansible Architecture

Machine where Ansible is installed.

Example:

Your Mac/Linux laptop or Jenkins server

Target servers managed by Ansible.

Example:

EC2 instances
Linux servers
Kubernetes nodes
Communication

Ansible mainly uses:

SSH for Linux
WinRM for Windows

No agent required.

Important Ansible Components
1. Inventory

List of servers.

Example:

[web]
10.0.0.10
10.0.0.11

[db]
10.0.0.20
2. Modules

Actual units of work.

Examples:

yum
apt
copy
service
user
file

Example:

- name: Install nginx
  yum:
    name: nginx
    state: present
3. Playbooks

YAML files containing automation steps.

Example:

---
- hosts: web
  become: yes

  tasks:
    - name: Install nginx
      yum:
        name: nginx
        state: present
4. Roles

Reusable structure for large projects.

Used in production heavily.

Example structure:

roles/
  nginx/
    tasks/
    handlers/
    templates/
    files/
    vars/
5. Handlers

Triggered only when changes occur.

Example:

- name: restart nginx
  service:
    name: nginx
    state: restarted
6. Variables

Used to make playbooks dynamic.

Example:

http_port: 80
7. Templates (Jinja2)

Dynamic configuration files.

Example:

listen {{ http_port }};

Best Practices
1. Use Roles

Makes code reusable.

2. Keep Secrets in Vault

Never hardcode passwords.

3. Use Idempotency

Ansible should not make unnecessary changes.

Example:
Running playbook multiple times gives same result.

Very important interview question.

4. Use Separate Inventories

Example:

inventory/dev
inventory/stg
inventory/prod

Important Interview Questions
Beginner Level
What is Ansible?

Automation and configuration management tool.

Why is Ansible called agentless?

No agent/software required on target servers.

Uses SSH/WinRM.

What is Inventory?

List of managed hosts.

Difference between Playbook and Module?
Module → Single task
Playbook → Collection of tasks
What is YAML?

Human-readable data serialization language used in playbooks.

Intermediate Level
What is Idempotency?

Repeated execution gives same result without unnecessary changes.

Difference between Static and Dynamic Inventory?
Static → Manual server list
Dynamic → Automatically fetched from cloud
What are Roles?

Reusable Ansible project structures.

What are Handlers?

Tasks triggered only on change notification.

What is Ansible Vault?

Used to encrypt sensitive data.

Advanced Level
Difference between Terraform and Ansible?
Terraform	Ansible
Infrastructure provisioning	Configuration management
Declarative	Procedural
Creates infra	Configures infra
How does Ansible work internally?
Reads inventory
Connects over SSH
Pushes temporary modules
Executes tasks
Removes temporary files
What is Ansible Galaxy?

Repository for reusable roles.

Explain Tags in Ansible

Run selective tasks.

Example:

ansible-playbook site.yml --tags nginx
What is become in Ansible?

Privilege escalation.

Example:

become: yes

Equivalent to sudo.
